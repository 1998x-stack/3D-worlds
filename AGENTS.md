# Agent instructions — 3D Worlds

This is a public, reusable **asset platform**, not a one-off scene demo.

## Invariants
- Canonical metadata lives in `catalog/models.json`. SQLite is generated by `python3 scripts/catalog.py build` and is **not** the source of truth.
- Stable `asset.id` never changes once published. Use a new version or slug for materially different geometry.
- All dimensions are in meters, Y-up, floor origin, and model-local center is x=z=0.
- Add an SPDX license identifier and provenance for every contributed asset; don't import third-party meshes without rights checks.
- Generators return `THREE.Group`, never mutate a global scene, and use explicit naming for important mesh parts.
- Static Pages must not assume server-side Python, live SQLite connections, or a remote MCP endpoint.
- MCP tools are read-only with respect to caller projects; do not execute arbitrary catalog-supplied code.
- Do not say a binary GLB exists in the repository unless its file has been committed. Browser-side export is different from a committed binary.
- Check model count and tests dynamically. Avoid code paths that enumerate all assets on the server or construct a WebGLRenderer for every result when scaling past the starter set.
- Model source copying must include `primitives.js` helpers; a bare generator with a relative import is not a portable snippet.

## Quality gate
1. `python3 scripts/catalog.py validate`
2. `python3 scripts/catalog.py build`
3. `python3 -m unittest discover -s tests -v`
4. `npm install && npm run build`
5. `npm run test:ingest` checks the official GLB validator + batch publication.
6. Open gallery; verify search, inspector controls, clipboard source, exported GLB and deep link.
7. Run MCP inspector with `python services/mcp_server.py` after `pip install -r requirements-mcp.txt`.

Read `docs/architecture.md`, `docs/threejs-research.md` and
`.codex/skills/threejs-model-builder/SKILL.md` for the workflow.

## P0/P1/P2 quality gate

- At any catalog size, all card images **must** be real build-time renderer outputs,
  not live 45-context WebGL cards or AI-generated stock images.
- Run `npm run generate:assets && npm run verify:assets && npm run build && npm run test:gallery` before deploy.
- Report actual Meshopt binary sizes and LOD triangle counts; LOD ratios are approximate targets.
- `THREED_WORLDS_STORE=s3` must never contain hardcoded API keys or public bucket ACLs.
- Remote API uses a cursor/pagination; do not bundle 50K records into one static JS payload.
- For copied recipe assets, provide `recipe_engine.js` and all required helpers.
- Read `docs/p0-p1-p2-delivery.md` before modifying renderer, optimizer, or object storage.

## V0.4 collection guardrails
- `catalog/collections/v04.json` is a historical immutable collection manifest: 40 assets, 13 categories, source paths and declared bounding dimensions.
- Keep all 45 existing asset IDs unchanged; subsequent collections append rather than renumber.
- For any new kind of primitive, add geometry creation in `src/models/recipe_engine.js` and ensure the copy-to-game snippet includes this engine.
- Do not treat an unrigged stylized humanoid or scene prop as manufacturing-grade CAD.
- Run `tests/test_collection_v04.py` for each new asset to validate source-backed recipes before rendering.


## Portable Skill v2 contract

- The canonical authoring bundle is `.codex/skills/threejs-model-builder/`.
  `.claude/skills/threejs-model-builder/` and `.pi/skills/threejs-model-builder/`
  must have the **same entire resource tree and content**, not just matching
  `SKILL.md`.
- When changing model workflows, choose and read the relevant
  `references/*.md` on demand. Use `assets/` templates for briefs/reports and
  do not treat example.org license placeholders as real evidence.
- Run `python3 scripts/verify_skill_mirrors.py` and the read-only
  `python3 .codex/skills/threejs-model-builder/scripts/preflight.py` on
  every Skill change. See `docs/skill-architecture.md` for design decisions.
